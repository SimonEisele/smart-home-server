# Smart Home review — 4 October 2026

The project is a shared-household organiser built with Angular 21 and Django 6. The implemented features are a personalised widget dashboard, household accounts, calendar and meal attendance, menu planning, recipes and cooking, shopping lists, tasks, and cleaning schedules.

## Changes

- A consistent dark slate and mint visual system, local system fonts, visible active navigation, a dedicated overview link, larger touch targets, keyboard focus indicators, and responsive account popovers.
- Angular-controlled navigation replaces the duplicate Bootstrap JavaScript menu handlers. Bootstrap CSS remains for existing forms and layouts. Custom styles now load after Bootstrap.
- Dashboard cards fit the available viewport, while phones receive a readable stacked layout. Editing remains available through the dashboard controls. New dashboards include a shopping-list widget.
- Widget updates have independent debounce timers and a serial write queue. Rapid changes to different widgets no longer cancel one another. Saving/applying a named layout waits for pending writes; removal waits for confirmation from the backend. Save failures are visible.
- One token refresh pipeline is shared by guards, the expiry timer, and the API interceptor. Session-only logins restore correctly; refresh-token rotation, logout during a pending refresh, and switching accounts are handled. Temporary connection failures keep stored credentials. Backend credentials are only attached to requests to the configured backend.
- Switching households fetches the new user state and reloads household-dependent pages, preventing stale data from the previous household. The edit control only appears on the overview page.
- Private task detail actions use the same visibility rules as the task list. Completion attribution is saved only after the whole update is validated.
- Recorded zero attendance takes precedence over legacy availability. Menu recipe references must belong to the current household. Feature endpoints reject writes without an active household with a clear message.
- Shopping export deduplicates selected meals, validates person counts, honours an explicitly supplied zero, and implements `resetExisting` for the selected household/week while retaining manual items and other weeks.
- Calendar range queries include events that began before the range but overlap it. Invalid event types and end-before-start ranges are rejected.
- Local calendar dates no longer pass through UTC conversion. Weather forecasts select times in the location's timezone.
- Cooking quantities retain significant trailing zeros: `100` no longer becomes `1`. The recipe editor explicitly labels quantities as referring to the configured base servings, matching the existing export/cooking-overlay calculation. No stored recipe quantities were rewritten.
- Widget resize observers are disconnected on destruction. A global notification exposes failed backend requests instead of leaving errors only in the console.
- Portable UTF-8 Python requirements, working Angular test providers, corrected stale generated tests, and regression coverage.

## Verification

- Production Angular build passes. Existing initial-bundle and large-component-CSS budget warnings remain; the duplicate Bootstrap JavaScript bundle is removed.
- 41 frontend tests pass, including refresh races, storage persistence, credential scoping, rapid dashboard writes, quantity formatting, and local dates.
- 13 Django regression tests pass for task permissions/completion, attendance fallback, recipe isolation, shopping export, calendar overlap/validation, and missing households.
- Headless Chromium opens all nine feature/account routes without page errors using mocked API/weather data. Dashboard screenshots at 1440×900, 1280×800 and 390×844 verify responsive layouts. These screenshots demonstrate layout, not connectivity to a real installation.
- No production data or live household accounts were modified. The Raspberry Pi, wall tablet browser, live weather service, and physical devices were not available for end-to-end testing.

## Remaining findings

1. `backend/backend/settings.py` currently contains development settings: a committed secret, DEBUG enabled, wildcard hosts, and permissive CORS. Before public deployment, supply a private secret and configure production hosts/origins and HTTPS. The current production configuration was deliberately not guessed from a repository without access to the Pi/Nginx deployment.
2. `BLACKLIST_AFTER_ROTATION` is enabled but the SimpleJWT blacklist app is not installed. Enabling server-side refresh-token revocation requires installing the app and running its migrations as a coordinated deployment change.
3. `Smarthome` is an empty placeholder component without a route or backend device-control endpoints. Real device control cannot be repaired or verified from this implementation alone. Notes have also been removed from the implementation although the older model documentation mentions them.
4. Some feature forms still update optimistically; a failed request is now reported globally, but a full retry/rollback policy for every form would require additional feature-specific work. Cross-tab refresh coordination and long-running/offline tablet behaviour should be checked on the actual device.
5. The current ingredient catalogue is intentionally global. Its edit permissions and the intended visibility of shopping items marked `globalItem` need a product decision before changing ownership rules or stored data.
6. Dashboard data lives on the server; the theme/layout changes do not rewrite existing personalised widget positions. Very small saved cards may scroll internally; they can be resized in edit mode.

## Installation after review

Use the project's existing deployment procedure after merging. The Angular build must be installed where Nginx currently serves the frontend; the existing checked-in `backend/templates/frontend` bundle is not rebuilt or used by the Django URL configuration. Deploying backend source alone will not change the served frontend.

For local verification, use Python 3.13 or newer and a Node version supported by the Angular packages:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cd backend
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py test features users
../.venv/bin/python manage.py runserver
```

In a second terminal:

```bash
cd frontend
npm ci
npm test -- --watch=false
npm run build
npm start
```

No database schema changes are introduced by this pull request. Do not replace an existing production SQLite database with a new local development database.
